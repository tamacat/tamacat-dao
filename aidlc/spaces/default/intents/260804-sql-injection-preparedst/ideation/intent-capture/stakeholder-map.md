# Stakeholder Map — SQL パラメータ化（PreparedStatement 化）

## Key Stakeholders and Interests

| ステークホルダー | 役割 | 関心事 | Source |
|------------------|------|--------|--------|
| 開発者本人（tamacat） | 唯一のステークホルダー。実装者であり意思決定者 | 実装品質と後方互換性の両方に責任を持つ | [Q5] |
| tamacat-dao 本体に対する自動静的解析（例: CodeQL ワークフロー） | 人間ではない「指摘元」。監査主体の代替として機能する | tamacat-dao 本体の SQL インジェクション指摘がゼロになること | [Q9] [Q3] |

- 人間のセキュリティ監査担当者・指摘元は存在しない。 [Q9]
- この「指摘元」が、Q1=B の述べる利用アプリケーション側の監査／診断の主体と同一であるかは確認されていない（`## Assumptions & Open Questions` を参照）。 [Q1] [Q9]
- 準拠すべき特定の規格・基準を課す外部主体は存在しない。 [Q11]
- 外部のライブラリ利用者は存在しないため、ステークホルダーとして登場しない。 [Q2]

## Decision-Makers vs Influencers

| 区分 | 主体 | 内容 | Source |
|------|------|------|--------|
| 意思決定者 | 開発者本人（tamacat） | スコープと優先度を単独で決定する | [Q6] |
| 影響者 | なし | 決定に影響を与える他者は存在しない | [Q6] |

- 外部ライブラリ利用者の互換性要求が実質的な制約になる、という選択肢は選ばれておらず、影響者は存在しないとされている。public API の後方互換性を維持するという方針は、他者からの要求ではなく開発者本人が自ら定めたものである。 [Q6] [Q5] [Q12]

## Communication Requirements

| # | 要件 | 宛先 | 発生条件 | Source |
|---|------|------|----------|--------|
| CR-1 | CHANGELOG／リリースノートでの告知 | 将来の自分自身、および v1.6.1 からの移行時の記録 | 無条件（破壊的 API 変更の有無にかかわらず必要） | [Q13] [Q10] |
| CR-2 | マイグレーションガイド（移行手順ドキュメント） | 将来の自分自身 | 破壊的 API 変更がある場合のみ | [Q14] |

- CR-1 はセキュリティ修正である以上、変更内容を必ず記録するという方針に基づく。Q7 で示された「破壊的 API 変更がある場合」という条件は、Q13 により無条件要件に更新された。 [Q13] [Q7]
- CR-2 の発生条件は、public API の後方互換性を維持するという方針（intent-statement.md の `## Initial Scope Signal` を参照）の下では発動しない見込みである。 [Q14] [Q12]
- 告知は外部の受け手を前提としない。現時点で外部の受け手は存在しない。 [Q10] [Q2]
- 定期的な報告サイクル（レポート頻度）については、回答された要件に含まれていない。 [Q7]
- ローカルでのみ作業し git push しない方針が依頼時点で示されており、外部への公開を伴う告知は当面発生しない。 [desc]

## Assumptions & Open Questions

- [assumption] 「自動静的解析」を唯一の指摘元ステークホルダーとして扱っているが、それが tamacat-dao 本体を対象とするものである以上、Q1=B が述べる利用アプリケーション側の監査／診断指摘の主体と同一であるとは確認されていない。利用側アプリケーションの監査主体が別に存在する可能性は排除されていない。 [Q1] [Q9]
- [assumption] CR-2 の発生条件（破壊的 API 変更の有無）は、public API の後方互換性を維持するという方針の下では発動しない見込みであるが、その方針で SM-1 が達成可能かは未検証であるため、Application Design（2.6）の結果次第で発動しうる。 [Q14] [Q12] [Q3]
